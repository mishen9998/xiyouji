# 战败返回主菜单

日期：2026-09-17。基于 75981d6，仅更新本机演示。

## 修复

- 单人服务端确认 `battleOver=true` 且 `victory=false` 后，显示战败提示、清理当前会话状态并 `replace('/menu')`，不进入地图/奖励/下一层。
- 联机仅在当前房间整场战败时返回主菜单，同时解除本地房间订阅与恢复指针；个别成员倒下、队伍仍在战斗时保留观战。其他房间的旧战败快照不能结束当前房间。
- 终局处理防重入；异步战斗读取完成后不能用“战斗尚未开始”的备用跳转覆盖主菜单导航。
- 战败结果弹窗的备用按钮明确为“返回主菜单”。读取 HP=0 的旧存档不再提供继续游戏，即使取消确认也不重新激活该局。
- 不注销登录、不删除服务器存档，不更改胜利领奖及通关流程。保留原存档的用户主动删除入口。

## 验证

- 全量前端 29 个测试文件、147 项测试通过；新增战败导航回归 11 项（最终小改后单独重跑通过）。
- 类型检查、Docker 正式前端构建与 Maven 打包通过。本轮没有后端代码修改，不宣称重新执行完整后端测试。
- 独立 `127.0.0.1` 测试游客：单人第 18 回合以 4 HP 受到致命攻击后自动回到 `/menu`；加载该存档显示“本局已战败 / HP: 0/85”，按钮为“返回主菜单”。
- 同一测试游客的单成员联机测试房间：第 19 回合以 3 HP 受到致命攻击后自动回到 `/menu`。这是联机界面终局烟雾测试，不是双人/五人全流程覆盖。
- 测试页面已关闭，没有操作用户原来的 localhost 页面、账号或存档。演示更新没有改动 MySQL/Redis 数据卷。
- 无多智能体、无远程推送、无云服务器部署。
