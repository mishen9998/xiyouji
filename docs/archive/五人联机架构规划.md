# 五人联机架构规划

## 当前状态：5 角色单机已完成

5 个角色（孙悟空/猪八戒/沙僧/白龙马/唐三藏）均可单人游玩，各有专属卡牌和遗物。

## 架构现状

```
当前单机架构：
  客户端(Fetch API) → Spring Boot REST → GameService(单player) → SessionStore
                                    → BattleService(单玩家 vs 单敌人 FSM)
```

核心限制：`GameSession.player` 是单数，`BattleState` 只管理 1v1 战斗，无实时通信层。

#### 1.2 新增 WebSocket 配置

```java
// WebSocketConfig.java
@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {
    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws").setAllowedOriginPatterns("*").withSockJS();
    }
    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        registry.enableSimpleBroker("/topic/room", "/topic/battle");
        registry.setApplicationDestinationPrefixes("/app");
    }
}
```

#### 1.3 新增 RoomService

## Phase 2: 多人战斗系统重构（预计 3-4 周）

### 后端改造

#### 2.1 BattleState → MultiBattleState

```java
public class MultiBattleState {
    private Enemy enemy;                           // 共享敌人（或多敌人 List）
    private Map<String, GameCharacter> players;    // 5 个玩家
    private List<String> turnOrder;                // 出牌顺序队列
    private int currentTurnIndex;                  // 当前出牌玩家
    private boolean allPlayersEndedTurn;           // 全体结束回合
    // ...
}
```

#### 2.2 回合流程改造

```
当前单机流程:
  玩家出牌 → 玩家结束回合 → 敌人行动 → 玩家回合

五人联机流程:
  P1出牌 → P2出牌 → P3出牌 → P4出牌 → P5出牌
  → 全体结束回合 → 敌人行动 → 新一轮（重新发牌）
```

关键变化：
- 每个玩家独立能量和手牌
- 按序出牌，唐三藏治疗卡可作用于队友
- 全体玩家点击"结束回合"后敌人才行动
- WebSocket 广播每次出牌/受伤/Buff 变化

#### 2.3 BattleService 改造

```java
// 新方法签名
MultiBattleState startMultiBattle(String roomId);
MultiBattleState playCard(String roomId, String userId, int handIndex);
MultiBattleState endPlayerTurn(String roomId, String userId);
void broadcastBattleEvent(String roomId, BattleEvent event);  // WebSocket 推送
```

### 前端改造

- `BattleView.vue` 改为显示 5 个玩家面板 + 敌人
- 当前出牌玩家高亮，其他玩家观战
- 唐三藏治疗卡牌可选择目标队友

## 技术选型

| 组件 | 技术 | 说明 |
|------|------|------|
| 实时通信 | Spring WebSocket + STOMP | 原生集成 Spring Boot，无需额外中间件 |
| 房间状态 | Redis | 已有 Redis 基础设施，房间状态 TTL 自动过期 |
| 身份认证 | JWT（已有） | 复用现有 User 模型和 JwtUtil |
| 前端通信 | SockJS + Stomp.js | Vue 3 composable 封装 |
| 断线重连 | Redis 持久化 + 心跳检测 | 玩家断线 60s 内可重连 |

## 迁移风险与策略

1. **向后兼容**：单人模式保留，`GameSession.player` 不删除，新增 `players` 字段
2. **渐进式**：先实现房间系统（Phase 1），验证 WebSocket 通信，再重构战斗
3. **测试策略**：单人模式 31 个测试保持通过，新增多人模式测试
4. **数据迁移**：Room 数据新建表，不影响现有 GameSession 结构
