本地准备：验证与配置

在本地电脑完成以下准备工作，确保部署文件完整且安全配置到位。

1.1 确认部署包已生成
部署包位于桌面"西游记"文件夹中：
📁 C:\Users\20126\Desktop\西游记\西行部署包.zip (约155MB)
1.2 修改环境变量密码（重要！）
解压zip后，用记事本打开 .env.cloud 文件，修改默认密码：
# 修改前（默认值，不安全） DB_PASSWORD=xiyouji2026 JWT_SECRET=xiyouji-prod-secret-2026-change-this-256bits-key # 修改后（你的强密码，示例） DB_PASSWORD=MyStr0ng@Pass2026! JWT_SECRET=a8f3k2j9s5d1q7w4e6r8t3y6u9i2o5p8a1s4d7f0g3h6j9k2l5
数据库密码建议12位以上，包含大小写字母、数字和特殊符号。JWT密钥建议32位以上随机字符串。
1.3 重新压缩为zip
修改完密码后，将所有文件重新压缩为zip包，准备上传。
如果你不想修改密码（仅测试用），可以直接使用原始zip包上传，但生产环境强烈建议修改！
2
服务器准备：安装Docker

登录腾讯云宝塔面板，安装Docker运行环境。

2.1 登录宝塔面板
在浏览器中访问你的宝塔面板地址（通常是 http://114.132.55.119:8888），输入账号密码登录。
2.2 安装Docker管理器
在宝塔面板左侧菜单操作：
👉 左侧菜单点击「软件商店」 👉 搜索栏输入「Docker」 👉 找到「Docker管理器」点击「安装」 👉 等待安装完成（约1-2分钟）
如果搜索不到Docker管理器，也可以在终端中手动安装：
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
2.3 验证Docker安装
在宝塔面板左侧点击「终端」，执行以下命令验证：
[root@localhost ~]# docker --version Docker version 24.0.x, build xxxxxx [root@localhost ~]# docker compose version Docker Compose version v2.x.x
如果 docker compose 命令不存在，说明Compose插件未安装，执行：
yum install docker-compose-plugin -y
2.4 配置Docker镜像加速（推荐）
国内服务器拉取Docker镜像较慢，配置阿里云加速器：
[root@localhost ~]# mkdir -p /etc/docker [root@localhost ~]# cat > /etc/docker/daemon.json << 'EOF' { "registry-mirrors": [ "https://your-id.mirror.aliyuncs.com", "https://docker.mirrors.ustc.edu.cn" ] } EOF [root@localhost ~]# systemctl daemon-reload [root@localhost ~]# systemctl restart docker
阿里云加速器地址需要到阿里云容器镜像服务控制台获取你专属的加速地址。

开放端口：防火墙配置

需要在两个层面开放端口：腾讯云安全组 + 宝塔防火墙。

3.1 腾讯云安全组放行端口
登录腾讯云控制台，配置安全组规则：
👉 登录 https://console.cloud.tencent.com/ 👉 进入「云服务器」→「安全组」 👉 找到你的服务器绑定的安全组，点击「编辑规则」 👉 添加入站规则： 端口 协议 来源 策略 8080 TCP 0.0.0.0/0 允许 # 游戏访问端口（必须） 8888 TCP 0.0.0.0/0 允许 # 宝塔面板（如已开放则跳过） 22 TCP 0.0.0.0/0 允许 # SSH连接（如已开放则跳过）
3307（MySQL）和6379（Redis）端口不要对外开放！它们仅在Docker内部网络通信，对外暴露有安全风险。
3.2 宝塔面板防火墙放行
在宝塔面板中也需放行8080端口：
👉 宝塔面板左侧 →「安全」 👉 放行端口输入「8080」→ 点击「放行」 👉 确认状态显示「已放行」
3.3 验证端口连通性
在本地电脑浏览器中访问以下地址测试端口是否畅通：
🌐 http://114.132.55.119:8080 # 如果显示502/503/连接超时，说明端口未放行或Docker未启动 # 如果显示404/空白页，说明端口畅通但应用未部署（正常，后续步骤会解决）

上传文件：部署包传输

将155MB的部署包上传到服务器，提供两种方式。

方式A：宝塔面板上传（推荐，简单）
通过宝塔面板的文件管理器上传：
👉 宝塔面板左侧 →「文件」 👉 进入根目录 / 或 /www/wwwroot/ 👉 新建文件夹 xiyouji 并进入 👉 点击右上角「上传」按钮 👉 选择本地的 西行部署包.zip 上传 👉 等待上传完成（约155MB，视网速5-15分钟）
方式B：SCP命令行上传（快速）
如果你熟悉命令行，可以用scp直接传输：
# 在本地电脑 PowerShell 中执行 scp C:\Users\20126\Desktop\西游记\西行部署包.zip root@114.132.55.119:/root/
如果SSH使用非默认端口（如22222），加 -P 参数：scp -P 22222 ...
4.3 解压部署包
在宝塔终端中执行：
# 创建部署目录 [root@localhost ~]# mkdir -p /www/wwwroot/xiyouji # 如果用宝塔面板上传到了 xiyouji 目录，则直接在此目录操作 [root@localhost ~]# cd /www/wwwroot/xiyouji # 解压 [root@localhost xiyouji]# unzip 西行部署包.zip # 验证文件结构 [root@localhost xiyouji]# ls -la total 4 drwxr-xr-x backend/ -rw-r--r-- .env.cloud -rw-r--r-- deploy-cloud.sh -rw-r--r-- docker-compose-cloud.yml [root@localhost xiyouji]# ls -lh backend/target/ -rw-r--r-- xiyouji-roguelike-1.0.0.jar 157M
如果 unzip 命令不存在，安装：yum install unzip -y
4.4 修改脚本权限
[root@localhost xiyouji]# chmod +x deploy-cloud.sh
5
执行部署：一键启动

运行部署脚本，Docker将自动拉取镜像、构建应用、启动所有服务。

5.1 执行一键部署脚本
在部署目录下执行：
[root@localhost xiyouji]# bash deploy-cloud.sh ============================================ 西游记云服务器部署脚本 ============================================ [1/6] 检查环境... OK Docker: Docker version 24.0.x Compose: Docker Compose version v2.x.x [2/6] 检查 JAR 文件... OK (157M) [3/6] 加载环境变量... OK [4/6] 停止旧容器... [5/6] 构建并启动容器（首次约3-5分钟）... # 这里会拉取 MySQL、Redis 镜像，构建应用镜像 # 首次拉取镜像约需要 3-8 分钟（取决于网速） [6/6] 等待应用启动... # 脚本会循环检测健康状态，最多等待90秒 ......(等待中) ============================================ 部署成功！ ============================================ 访问地址: http://114.132.55.119:8080 健康检查: http://114.132.55.119:8080/actuator/health
首次部署需要拉取MySQL(~500MB)和Redis(~30MB)镜像，加上构建应用镜像，总共需要5-10分钟。后续重启只需几秒。
5.2 如果脚本失败 - 手动分步执行
如果一键脚本失败，可以手动分步操作：
# 步骤1: 手动构建应用镜像 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml build # 步骤2: 启动 MySQL 和 Redis [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml up -d mysql redis # 步骤3: 等待数据库就绪（约15秒） [root@localhost xiyouji]# sleep 15 # 步骤4: 启动应用 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml up -d app # 步骤5: 查看启动日志 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml logs -f app
5.3 检查容器运行状态
[root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml ps NAME IMAGE STATUS PORTS xiyouji-mysql mysql:8.0 Up 2 minutes (healthy) 0.0.0.0:3307->3306/tcp xiyouji-redis redis:7-alpine Up 2 minutes (healthy) 0.0.0.0:6379->6379/tcp xiyouji-app xiyouji-backend-app Up 1 minute (healthy) 0.0.0.0:8080->8080/tcp
三个容器的状态都应显示 "Up" 和 "(healthy)"。如果显示 "unhealthy" 或 "Restarting"，请查看日志排查。

日常运维：日志与更新
7.1 查看实时日志
# 查看所有容器日志 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml logs -f # 只看应用日志 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml logs -f app # 查看最近100行日志 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml logs --tail=100 app
7.2 重启服务
# 重启所有服务 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml restart # 只重启应用（不影响数据库） [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml restart app # 停止所有服务 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml down # 启动所有服务 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml up -d
7.3 更新游戏版本（一键脚本方式 - 推荐）
当你修改了代码需要更新时，只需三步：本地构建 → 上传JAR → 服务器执行更新脚本。
📌 更新流程概览：
本地（双击 build-update.ps1）→ 自动构建前端+后端 → 生成 西行更新包.zip（约160MB）
上传（宝塔面板）→ 上传zip到服务器 → 解压覆盖
服务器（执行 update-cloud.sh）→ 只重建App镜像 → 重启应用
# ===== 第一步：本地一键构建 ===== # 在本地电脑 PowerShell 中执行 C:\> powershell -ExecutionPolicy Bypass -File C:\Users\20126\Desktop\西游记\build-update.ps1 # 脚本会自动完成： # 1. 构建前端 (vite build) # 2. 复制前端资源到后端 static 目录 # 3. 构建后端JAR (mvn clean package) # 4. 打包成 西行更新包.zip（仅含JAR + update-cloud.sh） # 输出: C:\Users\20126\Desktop\西游记\西行更新包.zip # ===== 第二步：上传到服务器 ===== # 宝塔面板上传 西行更新包.zip 到 /www/wwwroot/xiyouji/ # 终端解压覆盖旧文件： [root@localhost xiyouji]# cd /www/wwwroot/xiyouji [root@localhost xiyouji]# unzip -o 西行更新包.zip # -o 参数表示覆盖已有文件，不提示 # ===== 第三步：服务器执行更新 ===== [root@localhost xiyouji]# bash update-cloud.sh # 脚本会自动： # 1. 检查新JAR文件 # 2. 重新构建 app 镜像（不影响 MySQL/Redis） # 3. 重启 app 容器 # 4. 等待健康检查通过
增量更新只重建应用镜像，不重新拉取MySQL/Redis镜像，整个过程约2-3分钟。数据库数据不会丢失。
7.3.1 只改了前端代码的快速更新
如果只改了Vue前端代码（UI、样式等），更新流程一样，因为前端资源已打包进JAR中。
# 同样执行 build-update.ps1 即可 # 脚本会自动检测并重新构建前端 → 打包进JAR C:\> powershell -ExecutionPolicy Bypass -File C:\Users\20126\Desktop\西游记\build-update.ps1
7.3.2 只改了配置文件的更新
如果只改了 .env.cloud 或 docker-compose-cloud.yml，不需要重新构建JAR：
# 1. 上传新的配置文件到服务器 # 2. 重启所有容器使配置生效 [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml down [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml up -d
down 不会删除数据卷，用户数据安全。但 app 容器会短暂停机（约30秒-1分钟）。
7.4 设置开机自启
Docker容器已配置 restart: unless-stopped，服务器重启后会自动恢复。但需确保Docker服务本身开机自启：
[root@localhost ~]# systemctl enable docker [root@localhost ~]# systemctl status docker

故障排查：常见问题
问题1：访问 http://114.132.55.119:8080 超时
# 检查1：腾讯云安全组是否放行8080端口 # 检查2：宝塔防火墙是否放行8080端口 # 检查3：容器是否正常运行 [root@localhost ~]# docker compose -f /www/wwwroot/xiyouji/docker-compose-cloud.yml ps # 检查4：端口是否被监听 [root@localhost ~]# netstat -tlnp | grep 8080
问题2：应用容器一直 Restarting
# 查看应用日志找原因 [root@localhost ~]# docker compose -f docker-compose-cloud.yml logs app # 常见原因： # 1. 数据库未就绪 → 等待15秒后重试 # 2. JPA validate失败 → 检查数据库schema是否匹配 # 3. 内存不足 → 检查服务器可用内存 [root@localhost ~]# free -h
问题3：内存不足（OOM）
2核2G服务器内存紧张，可优化配置：
# 查看内存使用 [root@localhost ~]# free -h total used free available Mem: 1.8G 1.5G 300M 200M # 添加Swap交换分区（如未配置） [root@localhost ~]# fallocate -l 2G /swapfile [root@localhost ~]# chmod 600 /swapfile [root@localhost ~]# mkswap /swapfile [root@localhost ~]# swapon /swapfile [root@localhost ~]# echo '/swapfile swap swap defaults 0 0' >> /etc/fstab
问题4：数据库连接失败
# 检查MySQL容器是否正常 [root@localhost ~]# docker compose -f docker-compose-cloud.yml logs mysql # 手动测试数据库连接 [root@localhost ~]# docker exec -it xiyouji-mysql mysql -uroot -p # 输入 .env.cloud 中设置的 DB_PASSWORD
问题5：Docker拉取镜像超时
# 配置镜像加速器（见阶段2.4） # 或手动拉取镜像 [root@localhost ~]# docker pull mysql:8.0 [root@localhost ~]# docker pull redis:7-alpine # 拉取完成后再执行部署 [root@localhost ~]# docker compose -f docker-compose-cloud.yml up -d --build
问题6：需要完全重置
# 停止并删除所有容器和数据卷（⚠️ 会丢失数据！） [root@localhost xiyouji]# docker compose -f docker-compose-cloud.yml down -v # 重新部署 [root@localhost xiyouji]# bash deploy-cloud.sh
down -v 会删除数据库数据卷，所有用户数据将丢失！仅用于完全重置场景。
